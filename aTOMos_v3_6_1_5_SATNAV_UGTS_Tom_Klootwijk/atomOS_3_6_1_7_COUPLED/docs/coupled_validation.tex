\subsection{Evidence that both directions actually execute}
Counterfactual native trajectories share observations while changing the initial
word: position and velocity change, and later geometric drive changes. A second
pair shares its initial state while changing target geometry: drive and J/K state
change, then the physical trajectory changes. Edited Boolean equations also change
both state and later predicates. These are executed causal comparisons, beyond
agreement between two implementations.

Known free-motion, constant-force and diagonal-spring updates are checked against
closed forms of the stated discrete method. Off-diagonal generalized eigenmodes,
signed coefficients, missing observations, whole-word absorption, chart-domain
cases and numerical failure semantics are exercised. CPU regression checks also
retain small independent eigenmodes beside a stiffness of $10^{308}$.

\section{Coupled handoff evidence and reproducibility}
The actual 256-row SATNAV stream produces 253 observation-driven advances and three
prediction advances. There are 51 J/K changes across nine distinct word states.
At unavailable-observation epochs 250, 251 and 252, modeled motion continues by
approximately 2.10713 m, 1.61596 m and 1.24055 m respectively. Residual-alert epoch
253 remains an input observation with its diagnostic intact.

A separate publication audit checks every complete native trace binding, original
solver/epoch/residual/clock/variance record, both key encodings, full time, winding,
Up and hoop, all 255 state-carry links, all 256 state-dependent stiffness sums and
every hash-chain record. Its implementation reads the output independently from
the publisher. Original solver records remain distinct from modeled positions.

\subsection{Reproduce the full native fixture suite}
\begin{lstlisting}
python tools/validate_coupled.py \
  --binary bin/windows/cpu/coupled_kernel.exe \
  --backend cpu --out results/my_cpu_validation
python tools/validate_coupled.py \
  --binary bin/windows/cuda/coupled_kernel.exe \
  --backend cuda --out results/my_cuda_validation
compute-sanitizer --tool memcheck --error-exitcode 99 \
  bin/windows/cuda/coupled_kernel.exe \
  --input results/my_cuda_validation/compiled \
  --out results/my_memcheck --backend cuda
python tools/coupled.py \
  --input results/my_cuda_validation/model.json \
  --out results/my_memcheck_replay --verify results/my_memcheck
\end{lstlisting}
The replay-only command labels execution as not run because it reads an existing
trace; the preceding native command and sanitizer log establish that execution.
The native report retains actual backend/device identity and binary/model hashes.

\subsection{Toolchain and limits of these results}
The builds use MSVC 19.44.35221.0 and NVIDIA CUDA compiler 12.8.61. CUDA executes
on an NVIDIA GeForce RTX 5070 Ti Laptop GPU, compute capability 12.0, with driver
591.59. Short build directories avoid this workspace's long Windows scratch paths.
Python replay uses NumPy 2.1.2. CPU Address/UndefinedBehavior Sanitizer was not run
in this Windows release; its earlier Linux record remains archived.

These checks establish the declared coupled implementation on the supplied finite
fixtures. Physical coefficients are editable model inputs; this release has not
calibrated them against a measured mechanical system or validated live GNSS data.
No general switched-system convergence or measured speedup is inferred. The new
blend, encoders and mechanical matrix are fully specified CGK-R1 definitions.
They do not purport to recover unavailable original M2 equations.
